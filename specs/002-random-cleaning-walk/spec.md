# Feature Specification: Roomba-like Random Walk Cleaning

**Feature Branch**: `002-random-cleaning-walk`  
**Created**: 2026-03-21  
**Status**: Draft  
**Input**: User description: "既存のrumba同様のランダム走行での掃除をする機能。"

## Clarifications

### Session 2026-03-21

- Q: 低バッテリー時の動作はどうするか？ → A: 開始時は閾値未満で拒否、実行中は閾値未満でドック復帰を試行し失敗時停止。
- Q: ドック復帰試行時間は何秒か？ → A: 180秒。
- Q: センサー入力断時の挙動はどうするか？ → A: 連続1秒超で安全停止し、復帰後は手動再開のみ許可。
- Q: 狭所で進捗が出ない場合の脱出はどうするか？ → A: その場180度旋回を1回実施。
- Q: 清掃中の重複開始要求はどう扱うか？ → A: 状態変更なしで成功扱い（冪等）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ランダム走行清掃を開始・停止する (Priority: P1)

利用者として、ルンバ同様のランダム走行清掃をワンアクションで開始し、必要時に即時停止したい。これにより、地図作成や手動操作なしでも掃除を実行できる。

**Why this priority**: 本機能の中核価値そのものであり、これが成立しないと「既存ルンバ同様の清掃」を提供できないため。

**Independent Test**: ロボットを待機状態に置き、ランダム清掃開始コマンドを送信する。ランダム移動と清掃動作が始まり、停止コマンドで停止すれば本ストーリー単体で価値を確認できる。

**Acceptance Scenarios**:

1. **Given** ロボットが待機状態でセンサーと駆動系が正常、**When** ランダム清掃開始コマンドを受ける、**Then** ロボットは前進・旋回を組み合わせたランダム走行を開始し清掃状態になる。
2. **Given** ロボットがランダム清掃中、**When** 停止コマンドまたは緊急停止が発行される、**Then** 1制御周期以内に走行を停止し安全停止状態へ遷移する。

---

### User Story 2 - 接触・危険を検知して安全に振る舞う (Priority: P2)

利用者として、ランダム走行中に段差や危険状態を検知した場合は安全側に制御されてほしい。これにより、ハードウェア損傷や事故リスクを下げられる。

**Why this priority**: ランダム走行は環境依存で予測が難しいため、安全制御がないと実運用できないため。

**Independent Test**: ランダム清掃中に段差検知または障害物近接イベントを疑似入力し、回避または停止遷移が実行されることを確認する。

**Acceptance Scenarios**:

1. **Given** ランダム清掃中、**When** 段差リスクが検知される、**Then** ロボットは即時停止し後退または回避方向へ再遷移して清掃を継続するか、安全停止する。
2. **Given** ランダム清掃中、**When** 非壁障害物との接触が検知される、**Then** ロボットは接触継続を回避する方向へ短時間で姿勢を変更し、再度ランダム走行へ復帰する。

---

### User Story 3 - 清掃実行状態を把握する (Priority: P3)

利用者として、ランダム清掃中の状態（実行中・停止中・異常）を常時把握したい。これにより、挙動異常時に早く介入できる。

**Why this priority**: 清掃そのものより優先度は下がるが、ロボット制御の運用品質を担保するために必須の補助価値があるため。

**Independent Test**: 清掃開始・通常走行・安全停止・再開の各イベントを順に発生させ、状態表示とログが一貫して更新されることを確認する。

**Acceptance Scenarios**:

1. **Given** ロボット状態が遷移する、**When** 状態更新が発生する、**Then** 実行状態と主要イベントが遅延なく記録され操作者が確認できる。

---

### Edge Cases

- 清掃開始要求時にバッテリー残量が開始閾値未満の場合は開始を拒否し、理由を状態として返す。
- センサー入力断が連続1秒を超えた場合は安全停止し、自動再開せず手動再開のみ許可する。
- 狭所で進捗が出ない場合は、その場180度旋回を1回だけ実施し、通常ランダム走行へ復帰する。
- 清掃中に二重で開始コマンドを受けた場合は、状態変更なしで成功応答を返す（冪等）。
- 清掃中にバッテリー残量が実行閾値未満へ低下した場合、180秒のドック復帰試行が失敗したときの停止条件と通知方法。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、待機状態のロボットに対してランダム走行清掃を開始できなければならない。
- **FR-002**: システムは、ランダム走行中に前進と旋回を組み合わせた非固定パターン移動を継続的に生成しなければならない。
- **FR-003**: 利用者は、ランダム走行清掃を任意のタイミングで停止できなければならない。
- **FR-004**: システムは、緊急停止要求を常時受け付け、受信後1制御周期以内に駆動を停止しなければならない。
- **FR-005**: システムは、段差リスク検知時に安全停止または安全回避へ遷移しなければならない。
- **FR-006**: システムは、非壁障害物との接触または近接リスク時に接触継続を避ける動作へ遷移しなければならない。
- **FR-007**: システムは、ランダム清掃の現在状態（待機、清掃中、安全停止、異常）を外部から参照可能にしなければならない。
- **FR-008**: システムは、状態遷移と主要安全イベントを時系列で記録しなければならない。
- **FR-009**: システムは、センサー不良または制御異常を検知した場合、清掃継続より安全停止を優先しなければならない。
- **FR-010**: システムは、同一セッション内で開始済み状態への重複開始要求を受けた場合、状態変更なしで成功応答を返し、挙動を不安定化させてはならない。
- **FR-011**: システムは、清掃開始要求時にバッテリー残量が開始閾値未満の場合、清掃開始を拒否し理由を報告しなければならない。
- **FR-012**: システムは、清掃中にバッテリー残量が実行閾値未満へ低下した場合、180秒間ドック復帰を試行し、復帰できないときは安全停止へ遷移しなければならない。
- **FR-013**: システムは、清掃中にセンサー入力断が連続1秒を超えた場合、即時に安全停止へ遷移しなければならない。
- **FR-014**: システムは、FR-013で安全停止したセッションについて、センサー復帰後も自動再開してはならず、利用者の明示的な手動再開操作があるまで停止状態を維持しなければならない。
- **FR-015**: システムは、狭所で進捗が出ないと判定した場合、脱出動作としてその場180度旋回を1回のみ実施し、その後は通常のランダム走行へ復帰しなければならない。

### Key Entities *(include if feature involves data)*

- **Cleaning Session**: 1回のランダム清掃実行を表す単位。開始時刻、終了時刻、終了理由、最終状態を持つ。
- **Robot Runtime State**: ロボットの現在実行状態を表す。状態種別、更新時刻、安全フラグ、異常フラグを持つ。
- **Safety Event**: 段差検知、緊急停止、センサー異常などの安全関連イベント。種別、発生時刻、対処結果を持つ。
- **Motion Decision**: ランダム走行で選択された移動判断。判断時刻、移動種別、継続時間、遷移理由を持つ。

## Assumptions

- 本機能は「既存ルンバ同様のランダム走行」を対象とし、地図ベース経路計画は対象外とする。
- 清掃開始前に最低限のセンサー健全性チェックは完了している前提とする。
- 壁接触は許容されるが、段差・ケーブル・人体などの非壁リスクは回避または停止を優先する。
- 低バッテリー時は「開始拒否（開始前）」と「ドック復帰試行後の安全停止（実行中）」を標準動作とする。
- センサー入力断が連続1秒超の場合は安全停止し、自動復帰しない。
- 狭所脱出はその場180度旋回1回を標準動作とする。
- 性能検証は室内の一般的な家庭環境（家具あり）を基準とする。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、清掃開始要求から5秒以内にランダム走行清掃が開始されたことを確認できる。
- **SC-002**: 緊急停止要求時、95%以上の試行で1制御周期以内に駆動停止が完了する。
- **SC-003**: 30分の標準清掃セッションにおいて、異常終了なしで走行継続できる割合が90%以上である。
- **SC-004**: 安全イベント発生時の状態遷移記録欠損率が1%未満である。
- **SC-005**: 検証担当者の90%以上が「既存ルンバ同等のランダム走行挙動」と判定する。
