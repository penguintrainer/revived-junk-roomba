# Feature Specification: Roomba577 マルチモード清掃システム

**Feature Branch**: `001-roomba-cleaning-modes`  
**Created**: 2026-03-10  
**Status**: Draft  
**Input**: User description: "ROS2の複数のパッケージを実装。Roomba577を活用して、部屋の掃除を実施。既存のランダム走行での掃除、Joy-Conによるマニュアル走行での掃除、amclなどに基づく自動走行での掃除を実現。自動走行時は壁には衝突しても構わないが、段差やケーブルなどの障害物はLiDARやRGB、RGBD情報を使って回避。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ランダム走行清掃 (Priority: P1)

ユーザーがシステムを起動し「ランダム走行モード」を選択すると、Roomba577 が Roomba 本来のランダム走行アルゴリズムで部屋を走行しながら清掃を行う。壁や家具への軽い接触は許容される。ユーザーは走行中にシステムの状態（バッテリー残量、走行距離、清掃時間）を確認でき、いつでも停止できる。

**Why this priority**: Roomba577 の既存機能を活用した最もシンプルな清掃モードであり、他のモードの基盤（Roomba との通信、モーター制御、状態監視）を構築する。これ単体で清掃としての価値を提供できる MVP。

**Independent Test**: Roomba577 をシリアル接続した状態で起動し、ランダム走行モードを開始。Roomba が自律的に走行・清掃を行い、状態がモニタリングでき、停止指示で安全に停止することを確認する。

**Acceptance Scenarios**:

1. **Given** Roomba577 がシリアル接続済みかつ充電十分な状態、**When** ユーザーがランダム走行モードを開始する、**Then** Roomba がランダムパターンで走行・清掃を開始し、走行状態が 1 秒以内にモニタリング可能になる
2. **Given** ランダム走行中の Roomba、**When** ユーザーが停止を指示する、**Then** Roomba が 1 秒以内に安全に停止する
3. **Given** ランダム走行中の Roomba、**When** Roomba が壁に接触する、**Then** Roomba が方向転換して走行を継続する
4. **Given** ランダム走行中の Roomba、**When** シリアル通信が途絶する、**Then** Roomba が安全に停止し、通信途絶をユーザーに通知する

---

### User Story 2 - Joy-Con マニュアル走行清掃 (Priority: P2)

ユーザーが Nintendo Joy-Con を使って Roomba577 を手動で操作し、特定のエリアを重点的に清掃する。左スティックで前進・後退・旋回を指示し、直感的にロボットを制御できる。ユーザーは自分の意志で掃除したい場所に Roomba を誘導できる。

**Why this priority**: ランダム走行で清掃しきれない特定エリアの重点清掃を可能にする。ランダム走行モード（P1）で構築した Roomba 通信基盤の上に、Joy-Con 入力による速度制御を追加する形で実装でき、ユーザーが直接介入して清掃の質を高められる。

**Independent Test**: Joy-Con を Bluetooth 接続し、マニュアル走行モードを開始。左スティック操作で Roomba が前後左右に応答し、スティックを離すと停止することを確認する。

**Acceptance Scenarios**:

1. **Given** Joy-Con が Bluetooth 接続済みかつ Roomba がシリアル接続済み、**When** ユーザーがマニュアル走行モードを開始しスティックを前方に倒す、**Then** Roomba が前進を開始し、操作から 200ms 以内に動き出す
2. **Given** マニュアル走行中、**When** ユーザーがスティックを離す、**Then** Roomba が即座に停止する
3. **Given** マニュアル走行中、**When** Joy-Con の Bluetooth 接続が切れる、**Then** Roomba が安全に停止し、接続切断をユーザーに通知する
4. **Given** マニュアル走行中、**When** ユーザーがスティックを左右に倒す、**Then** Roomba がその場で旋回し、倒した方向・角度に応じた速度で回転する

---

### User Story 3 - 自律走行清掃（障害物回避付き） (Priority: P3)

ユーザーがシステムに自律走行モードを指示すると、Roomba577 が自己位置推定に基づいて部屋を効率的に走行しながら清掃する。壁への接触は許容されるが、段差・ケーブルなどの危険な障害物は LiDAR やカメラ情報を使って検出・回避する。ユーザーは走行中の経路と障害物検出状況を確認できる。

**Why this priority**: 最も高度な清掃モードであり、自己位置推定（AMCL）、地図生成、障害物検出・回避など複数のサブシステムを統合する必要がある。P1・P2 で構築した Roomba 制御基盤とセンサ統合の上に構築される。

**Independent Test**: LiDAR を接続した状態で自律走行モードを起動。事前に作成した部屋の地図上で、Roomba が自律的に走行し、段差やケーブルなどの障害物を検出・回避しながら清掃を行うことを確認する。

**Acceptance Scenarios**:

1. **Given** LiDAR・カメラが接続済みで地図が読み込まれた状態、**When** ユーザーが自律走行モードを開始する、**Then** Roomba が地図上の未清掃エリアに向かって走行・清掃を開始する
2. **Given** 自律走行中、**When** LiDAR が走行経路上に段差やケーブル等の障害物を検出する、**Then** Roomba が障害物を回避して走行を継続する
3. **Given** 自律走行中、**When** Roomba が壁に接近する、**Then** Roomba は壁への接触を許容し、方向転換して走行を継続する（壁は回避対象外）
4. **Given** 自律走行中、**When** カメラが床面上の障害物（ケーブル、靴下等）を検出する、**Then** Roomba がその障害物を避けて迂回ルートを選択する
5. **Given** 自律走行中、**When** 自己位置推定の共分散が 0.5m² を超える、**Then** Roomba が安全に停止し、位置推定の不安定をユーザーに通知する

---

### User Story 4 - 走行モード切り替え (Priority: P4)

ユーザーがシステム稼働中に走行モード（ランダム走行・マニュアル走行・自律走行）を安全に切り替えられる。主な操作は Joy-Con のボタンで行い、ROS 2 CLI (ros2 service call) も補助・デバッグ用として使用できる。モード切り替え時には Roomba が一旦停止し、新しいモードに安全に遷移する。また、Joy-Con の特定ボタンで緊急停止を実行できる。

**Why this priority**: 各走行モード（P1-P3）が揃った後に、それらをシームレスに統合する機能。各モード単体でも使えるため、統合は最後に行う。

**Independent Test**: ランダム走行中にモード切り替えを指示し、Roomba が停止→新モード開始の遷移を安全に行うことを確認する。

**Acceptance Scenarios**:

1. **Given** ランダム走行中、**When** ユーザーがマニュアル走行モードへの切り替えを指示する、**Then** Roomba が停止し、Joy-Con による操作を受け付ける状態に遷移する
2. **Given** いずれかのモードで走行中、**When** ユーザーがモード切り替えを指示する、**Then** Roomba が 2 秒以内に安全に停止してから新モードに遷移する
3. **Given** モード切り替え中、**When** 切り替え先のモードに必要なハードウェアが接続されていない（例: Joy-Con 未接続でマニュアルモードへ切り替え）、**Then** 切り替えを拒否し、不足している接続をユーザーに通知する

---

### Edge Cases

- シリアル通信ケーブルが走行中に抜けた場合 → 通信途絶を検知し、安全停止（全モーター停止）を実行
- バッテリー残量が低下した場合 → 清掃を中断し、ユーザーに通知（Roomba のバッテリー警告をシリアル経由で検知）
- LiDAR データが一時的に欠落した場合（自律走行モード）→ 直近の安全な状態で停止し、センサ復旧を待機
- Joy-Con の左右両方が接続された場合 → 片方のみ（左 Joy-Con）で操作、もう片方は無視
- 狭い通路で段差と壁に同時に囲まれた場合 → 段差回避を壁接触より優先し、安全なルートがない場合は停止
- 清掃中にユーザーが Roomba を持ち上げた場合 → ホイールの空転を検知し、モーターを停止

- Q: マニュアル走行モードの最大速度は？ → A: 300mm/s
- Q: 自己位置推定の安全停止閾値は？ → A: AMCL共分散 0.5m²
- Q: モード切り替え・開始・停止の操作手段は？ → A: Joy-Conボタンを主、ROS 2 CLIを補助

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは Roomba577 とシリアル通信で接続し、走行指令（前進・後退・旋回・停止）を送信できなければならない (MUST)
- **FR-002**: システムは Roomba577 の状態（バッテリー残量、走行距離、バンパー接触、ホイール空転）をシリアル通信で取得できなければならない (MUST)
- **FR-003**: システムは 3 つの走行モード（ランダム走行・マニュアル走行・自律走行）を提供しなければならない (MUST)
- **FR-004**: ランダム走行モードでは、Roomba 本来のランダム走行アルゴリズムを起動し、清掃を実行できなければならない (MUST)
- **FR-005**: マニュアル走行モードでは、Joy-Con の左スティック入力を差動二輪の速度指令に変換し、Roomba に送信できなければならない。最大線速度は 300mm/s とする (MUST)
- **FR-006**: マニュアル走行モードでは操作入力から 200ms 以内に Roomba が応答しなければならない (MUST)
- **FR-007**: 自律走行モードでは、自己位置推定に基づいてボウスタス（ジグザグ）パターンで部屋の未清掃エリアを効率的に走行できなければならない (MUST)
- **FR-008**: 自律走行モードでは、LiDAR データを使って段差やケーブル等の低層障害物を検出できなければならない (MUST)
- **FR-009**: 自律走行モードでは、Intel RealSense D435i の RGBD データを使って床面上の障害物（ケーブル、靴下等）を検出できなければならない (MUST)
- **FR-010**: 自律走行モードでは、検出した障害物を回避するルートを選択できなければならない (MUST)
- **FR-011**: 自律走行モードでは、壁への接触は許容し、壁を回避対象に含めてはならない (MUST NOT)
- **FR-012**: すべての走行モードにおいて、通信途絶・センサ異常・バッテリー低下時に安全に停止できなければならない (MUST)
- **FR-013**: システムは走行モードの切り替え時に Roomba を安全に停止させてからモード遷移しなければならない (MUST)
- **FR-017**: モード選択・切り替え・緊急停止は Joy-Con のボタンで操作できなければならない (MUST)
- **FR-018**: モード選択・切り替え・停止は ROS 2 サービスインターフェースでも実行できなければならない (MUST)
- **FR-014**: システムは走行中の状態（現在のモード、走行速度、バッテリー残量、清掃時間）をリアルタイムでモニタリング可能にしなければならない (MUST)
- **FR-015**: 制御ループは 50Hz（20ms 周期）以上で動作しなければならない (MUST)
- **FR-016**: 各走行モードは独立したパッケージとして実装し、パッケージ間は標準的なメッセージインターフェースのみで通信しなければならない (MUST)

### Key Entities

- **走行モード (Driving Mode)**: ランダム走行・マニュアル走行・自律走行の 3 種類。現在のアクティブモード、モードごとの設定パラメータを保持
- **Roomba 状態 (Roomba State)**: バッテリー残量、走行速度、バンパー接触状態、ホイール空転状態、シリアル接続状態など、Roomba577 のリアルタイム状態
- **速度指令 (Velocity Command)**: 差動二輪ロボット向けの線速度・角速度指令。各走行モードから統一的なインターフェースで発行される
- **障害物 (Obstacle)**: LiDAR やカメラで検出された回避対象物。位置・種別（段差、ケーブル、その他）・サイズ情報を保持。壁は障害物に含めない
- **地図 (Map)**: 自律走行時に使用する部屋の 2D 占有格子地図。事前作成（SLAM）または走行中に更新
- **自己位置 (Robot Pose)**: 地図上での Roomba の現在位置と向き。自己位置推定の信頼度情報（AMCL 共分散）を含み、共分散が 0.5m² を超えた場合に安全停止を発動する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ランダム走行モードが起動してから 3 秒以内に Roomba が走行を開始する
- **SC-002**: Joy-Con 操作からRoomba の動作応答までの遅延が 200ms 以内である
- **SC-003**: 自律走行モードで 30 分間の走行中、段差・ケーブル等の障害物との接触が 0 回である
- **SC-004**: すべての走行モードにおいて、緊急停止指示から Roomba の完全停止まで 1 秒以内である
- **SC-005**: 通信途絶からシステムの安全停止までの時間が 500ms 以内である
- **SC-006**: 走行モードの切り替えが操作から 2 秒以内に完了する
- **SC-007**: 自律走行時に部屋面積の 80% 以上を 1 回の清掃セッションで走行する
- **SC-008**: システムの全ノードがライフサイクル状態を `/diagnostics` トピックに 1Hz 以上でパブリッシュする

## Assumptions

- Roomba577 のシリアルインターフェースは create_robot パッケージを介してアクセスし、Open Interface プロトコルに準拠する
- Joy-Con は Ubuntu の標準 Bluetooth スタックで HID デバイスとして認識される
- 自律走行の地図は事前の SLAM セッションで作成済みであることを前提とする（本機能スコープでの地図作成は含まない）
- 障害物検出は LiDAR（YDLIDAR T-mini Plus）の 2D スキャンデータを主に使用し、カメラ情報は補助的に使用する
- 壁と障害物の区別は、LiDAR データの高さ情報（段差検出）と RealSense D435i の深度・RGB画像によるオブジェクト認識で行う
- iPhone XR (Conduit) は IMU による自己位置推定補助に使用し、障害物検出には使用しない
- Nintendo Switch は制御用 PC として使用し、すべてのセンサとシリアル通信は Switch に接続される
- 1 部屋を清掃する使用シナリオを想定する（複数部屋の自動巡回は対象外）
